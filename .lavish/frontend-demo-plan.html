Minimum implementation

Few files, explicit contracts.

demo/index.html

Static shell and accessible regions: gallery, comparison, evidence.

demo/app.js

Exercise selection, chip actions, fine-tuned history, loading/error states, restart.

demo/server.py

Small local static server + `/api/chat` proxy; keeps credentials out of the browser and maps one adapter model id.

demo/fixtures.json

Deterministic base comparison snapshots and fine-tuned starter transcripts for all six exercises.

demo/smoke.py

One scripted session: chip click, adapter request, follow-up, restart, and no leaked code in the tuned fixture.

API shape

Send intent, not infrastructure.

POST /api/chat
{
"exercise_id": "exercise-gallery-even-or-odd",
"messages": [ ... ],
"temperature": 0
}

The browser never receives the API key. The proxy reuses the existing OpenAI-compatible client shape and points only at the saved Gemma 4 adapter service from #11. The base comparison is static content, so the GPU serves one model at a time.

Failure rule: an adapter failure must not erase the comparison. Keep the base snapshot visible and show “Fine-tuned tutor unavailable” with a retry action.

Acceptance checklist

Portfolio-ready means legible and honest.

  • ✓ First viewport shows both model names, the same learner moment, and which pane is live.
  • ✓ Chip actions trigger the same behavior in live and fixture modes.
  • ✓ Follow-up messages continue only the fine-tuned history; the base snapshot stays read-only.
  • ✓ Restart clears the fine-tuned conversation and restores both selected-exercise snapshots.
  • ✓ Loading, timeout, and adapter failure states remain understandable without hiding the comparison.
  • ✓ Evidence renders real artifacts from #16; no invented metrics.
  • ✓ Mobile collapses panes without hiding the model labels or composer.
  • ✓ Keyboard-accessible controls, visible focus, readable contrast, reduced-motion friendly.

Final direction

Keep the paired visual; serve only the fine-tuned tutor.

The base-model response remains a clearly labeled, curated comparison snapshot. Only the fine-tuned Gemma 4 adapter accepts new messages. This preserves the portfolio story, avoids double latency, and fits the single-GPU constraint.

Keep deferred

No accounts, hosting, free-form exercise authoring, or semantic auto-scoring.

The first release stays local and fixed-gallery. If the comparison becomes slow on the 31B hardware, preserve the prepared starter transcript and make live continuation an explicit action rather than adding streaming infrastructure prematurely.

Recommended next step

Implement the fixture-first first viewport now: a static base snapshot beside a live-capable fine-tuned pane, then wire only the adapter endpoint when training is complete. This gives you a recordable demo path without requiring both models to fit on the GPU.
